# 4.2 数据库设计

## 4.2.1 数据库设计原则

本系统采用 MySQL 8.0 关系型数据库进行结构化数据存储，数据库设计遵循以下原则：

**（1）规范化原则**：遵循数据库设计第三范式（3NF），消除非主属性对主键的传递依赖，减少数据冗余，避免数据更新异常、插入异常和删除异常，保证数据的一致性。系统将四类检查记录（CT、核磁、病理、肠镜）分别设计为独立的表，各有专属字段，避免将不同业务实体强行合并为一张宽表造成的字段稀疏和约束混乱问题。

**（2）关联性原则**：基于业务实体之间的关联关系，设计合理的主外键约束，明确实体之间的一对一、一对多关联关系，保证数据的关联性与完整性。核心关联链为：患者信息表作为数据中心节点，通过 patient_id 向外辐射关联检查记录、检验结果、医嘱记录、附件信息；用户表通过 user_id 关联各类数据的上传与操作记录；检验项目字典表通过 item_id 关联检验结果与预警规则。

**（3）性能优先原则**：针对高频查询字段和多条件组合查询场景，设计合理的单值索引与联合索引，避免全表扫描，提升查询性能。四类检查记录表均设计了"编号+患者+时间"联合索引用于批量导入重复检测，检验结果表设计了"患者+项目+时间"联合索引支撑指标历史趋势查询——该系统最高频的诊断辅助场景。

**（4）可扩展原则**：表结构设计预留扩展字段，适配后续业务需求的变化，无需大幅修改表结构即可实现功能扩展。预警规则表中预留了 rule_expression 字段用于存储组合条件表达式（JSON 格式），支持未来 AND/OR 复杂逻辑组合，无需新增字段。

**（5）安全合规原则**：严格遵循《医疗机构病历管理规定》《中华人民共和国个人信息保护法》《医疗卫生机构网络安全管理办法》等医疗行业法律法规，针对患者身份证号、手机号等敏感字段采用 AES 算法加密存储，所有业务表设计逻辑删除标识 is_invalid 字段实现数据可恢复的软删除机制，同时设计 create_time 和 update_time 字段记录数据的创建与更新时间。操作日志表（operation_log）设计为仅支持新增查询、不可修改删除，通过 AOP 切面自动记录操作前后的数据快照，满足医疗行业"全程留痕、100% 可追溯"的合规要求。

## 4.2.2 数据库 E-R 模型设计

基于系统需求分析中梳理的业务实体及其关联关系，系统数据库 E-R 模型以患者信息表（patient）为数据核心节点，向外辐射关联四类检查记录表（ct_examination、mri_examination、pathology_examination、enteroscopy_examination）、检验结果表（lab_result）、医嘱信息表（medical_order）和附件信息表（attachment），形成"一个患者→多次检查→多条检验结果→多份报告附件"的树状数据关联结构。

检验项目字典表（lab_item_dict）作为检验结果的基础数据支撑，通过 item_id 定义各项检验指标的编码、名称、单位与参考范围，同时关联预警规则表（warning_rule），为预警规则的配置提供标准化的指标参照。预警规则触发后生成预警记录（warning_record），预警记录同时关联触发规则与触发时的检验结果记录，形成完整的预警追溯链路。

用户权限体系采用经典的 RBAC 模型，通过用户表（user）、角色表（sys_role）、权限表（sys_permission），以及用户角色关联表（sys_user_role）、角色权限关联表（sys_role_permission）五张表，实现"用户→角色→权限"三级灵活的权限管理。用户表横向关联各类数据的录入操作，向下关联操作日志表（operation_log），实现全流程操作可追溯。

## 4.2.4 索引设计

针对系统高频查询场景，本章设计了覆盖核心业务表的关键索引，以保障系统在十万级数据量下的查询性能。索引设计遵循以下思路：主键采用自增 B-Tree 索引，外键字段建立普通索引支撑关联查询，高频组合查询字段建立联合索引减少回表开销，批量导入场景建立防重复联合唯一索引，用户认证与权限校验场景建立唯一索引确保数据唯一性。各表的索引汇总如表 4-22 所示。

索引设计的核心思路如下：

四类检查记录表（CT、核磁、病理、肠镜）均设计了"编号+患者+时间"联合索引（idx_import_dup），专门用于批量导入 Excel 与 XML 历史数据时的重复检测场景——以检查编号、患者编号、检查时间三个维度联合判定记录是否已存在，确保同一患者的同一次检查不会被重复导入入库。

检验结果表（lab_result）的核心联合索引 idx_patient_item_time 覆盖了"按患者查询某项检验指标的完整历史趋势"这一最高频的诊断辅助场景，使患者单项指标的时间序列折线图能够在百毫秒级响应，支撑临床快速判断指标变化趋势。

操作日志表（operation_log）以 user_id 和 operation_time 为维度建立单值索引，以 operated_table 和 related_record_id 建立联合索引，分别支撑按操作人追溯和按数据记录追溯双向审计需求。

RBAC 权限体系的两张关联表（sys_role_permission 和 sys_user_role）均采用联合唯一索引约束，从数据库层面阻止重复授权和重复分配，保障权限配置的一致性和准确性。
